# Hoenn & Seek 2.0: build roadmap

**What to build, in order, sized for one sitting each.** The design is in `2.0-plan.md` (section numbers below point there). How to work: `README.md`.

**Priority: quality over speed** (Bryan, Nov 25: "I'd rather things take longer but done well"). Parts are kept small so each one has room for edge-case testing and polish. Nothing gets cut for time.

**Status (Nov 26):** parts 1–2 done and merged (PRs #27, #28). **Part 3 is done** (PR #29, waiting for Bryan's mGBA test and merge). Next: part 4a (level caps). 1.0 is tagged `1.0` (commit `c0c62f19`).

## Sizing
- Each part targets **~40–50% of a 5-hour usage window**; nothing planned above ~55%. The headroom goes to testing and polish, not more content.
- S ≈ 30–40%, M ≈ 40–50%, L ≈ 50–55%.
- From 1.0: code-only systems are cheap; **new maps, multi-map scenes and art are expensive**; emulator testing with screenshot grids adds ~10–15%. A fresh session also spends a little on setup (toolchain install, first build ~10 min).
- If a part runs over, stop at a working build, commit, and carry the rest into the next part. Never end a session on a broken build.
- 🎮 = Bryan tests a debug patch in mGBA before the next part.

## Every part
**Unchanged from 1.0:** branch `v2-NN-<slug>` off `hoenn`, PR into `hoenn`. Release + debug build, ROM size delta, debug `.ups`, labeled screenshot grids, CLAUDE.md notes, roadmap status, untested items to `playtest-checklist.md`. Phone rule applies.

**New for 2.0:**
- Add the part's own **rumor/story lines** to the hint table (no big fill pass at the end).
- Set each event Pokémon's **special trait** (plan section 9) when it's created.
- Take flags and vars from the **phase's block** in `include/constants/hoenn_events.h` (part 1); daily/weekly events use the daily and weekly flags there.
- Re-run the overworld Pokémon generator if map objects changed.
- **Scene text first** for story-heavy scenes (starters, legendary chains, cameos): post the draft dialogue for Bryan to approve before scripting it.
- **Edge-case pass** before the PR, for every event:
  - wrong time, weekday or weather (nothing happens, or the right hint shows)
  - coming back after it's done (no replay, no duplicate rewards)
  - caught vs. knocked out vs. ran (each leaves the right state)
  - full party and full boxes when a Pokémon is given
  - saving and reloading partway through a chain
  - every text box read for wraps and tone

## Totals and order
- **~56 parts ≈ 25–30 five-hour windows.** No deadline; quality first.
- **Fixed order:** A → B before anything else (every event needs the helpers, weekday, weather or hints). Phase F last (it uses items from D and E). Part 33 after all events.
- **Flexible:** Phase C can interleave with D/E to break up the building work.
- **1.0 playtest:** Bryan's 1.0 playtest (1.0 roadmap part 20) hasn't happened. **1.0 saves load into 2.0** (save version 6 clears only the new area), so the playtest save can carry on into 2.0 builds. Fixes to 1.0 content still go on `v1.1-<slug>` branches merged into `hoenn`.
